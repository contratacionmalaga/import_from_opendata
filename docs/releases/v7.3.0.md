# Release 7.3.0

Fecha: 2026-09-09
Rama: `jarp/email-reporte-ejecucion-v7.3.0`

## Cambios

- Se mejora el asunto del correo de éxito para que sea más humano e informativo: estado, proceso (`con_filtros`/`sin_filtros`), origen (`LOCAL`/`INTERNET`) y número de cambios útiles.
- Se mejora el asunto del correo de error eliminando referencias a Málaga y usando el proceso operativo real.
- Se sustituye el cuerpo técnico `campo/valor` por un reporte HTML con resumen ejecutivo, métricas principales, resultado de persistencia, rendimiento, configuración aplicada y datos técnicos.
- El paso de notificación pasa el `OpenDataExecutionContext` completo para poder informar datos de configuración de la ejecución, como rango de lectura y códigos postales.
- Se añaden tests unitarios para fijar el asunto de éxito, el asunto de error y el contenido principal del cuerpo HTML.
- Se actualiza la versión Maven del aplicativo a `7.3.0`.
- `importar_atoms.ps1` incorpora `-CreateSchemaFirstRun` para crear esquema solo en la primera importacion planificada y usar `hibernate.hbm2ddl.auto=none` en el resto.
- `importar_atoms.ps1` e `importar_atom.sh` dejan de fijar la memoria Java en el script y leen `java.opts` desde `properties/runtime.properties` cuando existe.
- Si `properties/runtime.properties` no existe o no informa `java.opts`, los scripts usan el fallback conservador `-Xms12g -Xmx12g`.
- La variante `sin_filtros` pasa las entradas agrupadas por `Feed` mediante `ImportPersistencePlan.entriesByFeed()` para persistirlas sin reconstruir la agrupacion desde las listas del feed.
- `RepositoryImpl` persiste `entriesByFeed` cuando viene informado, asigna cada `Entry` a su `Feed`, mantiene `createdAt` en actualizaciones y libera las listas procesadas para reducir presion de memoria.

## Configuracion operativa

Para ajustar la memoria del proceso Java, crear en el entorno operativo:

```properties
java.opts=-Xms32g -Xmx32g
```

El fichero esperado es `properties/runtime.properties`, dentro del mismo directorio `properties` usado por la ejecucion. Esta configuracion no se versiona porque `properties/` pertenece a cada entorno.
