# Release 8.1.1

## Corte incremental entre feeds

La versión anterior detectaba un entry más antiguo que el máximo `updated` local, pero seguía
descargando el histórico para recoger bajas. Esto alargaba las importaciones INTERNET aun cuando
ya se había alcanzado el límite local.

Ahora `FeedHelper` termina la navegación antes de resolver o descargar el siguiente enlace.
El límite procede del entry con mayor `updated` en la base de datos para la sindicación solicitada,
no del valor numérico de su identificador ni de la fecha del fichero ATOM.

- Un `updated` estrictamente anterior al límite detiene el recorrido.
- Una fecha igual no lo detiene: puede haber otros entries con la misma fecha.
- Sin entries locales no hay corte incremental y se recorre la cadena completa.
- Se conservan las bajas de los feeds ya leídos, incluido el feed donde se alcanza el corte.
- No se leen las bajas de feeds posteriores al corte.

La corrección se aplica al navegador compartido de las variantes local/INTERNET que comparan
con datos existentes. No se añaden propiedades, dependencias ni migraciones respecto a 8.1.0.
Con datos existentes debe mantenerse `hibernate.hbm2ddl.auto=validate`.

## Validación

Las pruebas `FeedHelperNavigationTest` y `EntryProcessorSnapshotTest` comprueban el corte entre
feeds y la conservación del procesamiento de entradas con la misma fecha que el cursor local.
La validación real se realiza desde INTERNET, filtro postal 29, primero con ENCARGOS y después
con MAYORES, contrastando el commit, las estadísticas y los recuentos en `opendata_malaga`.
Los resultados se registran en `docs/auditorias/2026-09-27/resultado-internet-malaga-29.md`.

La batería completa pasó: 82 pruebas, cero fallos y errores, dos omitidas. Se generaron los
cuatro JAR operativos. La prueba real ENCARGOS confirmó el corte en el feed 2 y el commit:
2 entries insertados, 0 actualizados, 597 rechazados y 0 bajas; el total local pasó de 192 a 194.
Las estadísticas coinciden con los recuentos del lote; no hay duplicados ni entries sin feed.

En la base antigua de Málaga aparecieron columnas de auditoría obligatorias ya no mapeadas,
correspondientes al esquema anterior a la migración v7.5.2. Los intentos fallidos se revirtieron.
Para conservar esos datos se mantuvieron las columnas y se añadieron valores por defecto
reversibles a las columnas legacy; `log.updated_at` pasó a admitir NULL. No se tocaron las
columnas mapeadas de `entry` ni `log.created_at`. Los scripts de compatibilidad y rollback están
en `docs/auditorias/2026-09-27/`; se guardaron el esquema previo y las filas de `log` en el
directorio de evidencias local. Esta adaptación depende del esquema antiguo, no es un nuevo
requisito de 8.1.1 para bases ya migradas.
