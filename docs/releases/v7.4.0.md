# Release 7.4.0

## Cambios funcionales

- Se incorporan en `tendering_process` los campos `original_contracting_system_id`, `original_contracting_system_description`, `original_contracting_system_lot_id` y `original_contracting_system_lot_description`.
- Los identificadores se limitan a 50 caracteres y las descripciones se almacenan como `TEXT`.
- Se incluye la migración SQL aditiva para aplicar las columnas sin recrear tablas.

## Importación ATOM e integridad

- El parser rechaza DTD y entidades externas.
- La navegación ATOM falla ante enlaces iniciales inválidos, enlaces `next` inválidos o ciclos.
- El fin normal ocurre solo cuando el feed no contiene `next`.
- La carga incremental mantiene entradas con el mismo `updated` y sigue navegando para recoger bajas posteriores.
- Se añade exclusión distribuida MariaDB por tipo de sindicación para impedir importaciones simultáneas.

## Persistencia y diagnóstico

- Se añade instrumentación de apertura, JAXB/mapeo, filtrado, preparación, persistencia, flush y commit.
- Las métricas se calculan con reloj monotónico y se registran después del commit.
- Se evita mostrar secretos JDBC en los logs de Hibernate.
- Se añaden scripts para corpus ATOM y capturas JFR.
- El batch JDBC recomendado pasa a `300`.

## Validación

- Se amplían las pruebas de parser seguro, navegación de feeds, snapshots, rollback, cascadas MariaDB, bloqueo distribuido y mapeo de los nuevos campos.
- Prueba LOCAL reproducible: 100.323 entries leídas, 52.287 expedientes únicos persistidos y 2.046.730 inserciones verificadas.
- La referencia sobre esquema limpio alcanza `grafoYFlush` en 1 min 58 s con batch JDBC 300.

## Despliegue

1. Aplicar la migración de `tendering_process`.
2. Arrancar con `hibernate.hbm2ddl.auto=validate`.
3. Usar batch JDBC 300.
4. No usar `create` fuera de entornos de prueba.
